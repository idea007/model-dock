# 接入端

[English](client-demo.md) | **简体中文**

这是一个独立的接入应用：后端持有 **项目密钥**，浏览器管理应用功能。它通过网关的公开推理接口接入，不调用管理接口。demo 是可运行的接入示例，不是网关运行依赖，也不是多用户生产应用。

## 打开页面并连接 Model Dock

```sh
# 终端 1：模型供给、发布和项目权限
npm start
# 终端 2：接入应用
npm run demo -- --open
# 安装本地打包产物后也可以使用：
model-dock-demo --open
```

默认地址是 `http://127.0.0.1:4318`，可以直接打开或刷新，无需手动填写接入端本地会话令牌。`--open` 打开普通页面地址，不在 URL 中携带密钥。未连接时模型目录为空；接入端不提供模拟数据，也没有 `--mock` 启动模式。

1. 在服务端「模型与服务」发布模型，在「项目访问」创建限定模型范围的密钥。
2. 打开左侧「接入设置」，在独立页面的连接表单填写服务端 API 地址（通常为 `http://127.0.0.1:4317/v1`）及 `md_key_…` 项目密钥，点击「连接并读取模型」。管理员令牌会被拒绝。
3. 启用此应用需要的授权模型，配置功能并保存。
4. 在「应用体验」用默认模型或明确选择的候选运行功能。真实请求会使用所选上游的资源与额度。

「接入设置」与「应用体验」「功能与模型」并列于左侧导航，移动端也可访问，可通过 `/?view=settings` 直接打开。连接验证失败时显示错误，不保存无效密钥。已保存的连接在接入端重启后继续使用。

左侧「接口文档」（`/?view=api`）可展开查看服务端接口说明并复制 cURL 示例。尚未连接时也可以查阅，连接后示例使用接入设置中的服务端地址。

服务端保存模型开关、能力或思考深度后，在「接入设置」或「功能与模型」点击「刷新模型」即可同步，无需重新填写密钥。接入设置会显示可用授权模型数量与最近成功同步时间；重新打开页面也会更新目录。未保存的应用草稿会保留，其他页面对应用设置的并发修改仍会触发版本冲突。

内置功能包括自由对话、结构化提取；「内容处理」分组包含摘要、润色、翻译；「开发助手」分组包含代码讲解与审查。这些是实际请求使用的功能模板，初始状态没有绑定模型。

发送给网关的是模型 ID，不是应用功能 ID。撤销密钥、模型不可用、默认选择失效或思考等级不合法时会明确失败，不会自动换模型或重试。停止流式输出会取消网关请求。详见 [功能与模型设置](model-settings.zh-CN.md)。

可用 `--port 4328` 指定接入端端口。网关与接入端可以独立重启。

## 数据边界

| 所属 | 默认目录 | 内容 |
| --- | --- | --- |
| 服务端 | `~/.model-dock` | 上游凭证、模型发布、项目权限及兼容的旧别名 |
| 接入端 | `~/.model-dock-demo` | `client.json` 中的网关地址、项目密钥、目录缓存和应用偏好；本地会话令牌与单写者锁 |

`MODEL_DOCK_DEMO_HOME` 可改变接入端根目录。接入端自己执行版本检查和原子写入；项目密钥存于本地后端私有文件，文件权限 `0600`、目录 `0700`，**未加密**，不会通过状态接口返回或写入浏览器存储。浏览器自动建立本地会话，令牌仅保留在页面内存中，接入端进程重启后失效；重新打开页面会自动获取新会话。`npm run demo -- token` 仅供需要手动调用接入端 API 的本地脚本使用。Windows 请使用当前用户私有目录并设置相应 ACL。不要提交这些数据目录。

更换网关地址或项目密钥后，应用中的模型会关闭，保留原选择供复核。如果显式使用旧模拟模式的数据目录启动，模拟连接、模型缓存和绑定会清除，再填写真实服务端密钥接入。测试用模拟服务仅位于 `tests/fixtures`，不随应用打包。

## 接入端接口

这些接口属于接入端进程，与网关管理接口相互独立。静态资源、`/healthz` 和会话建立接口无需令牌，其余接口需要本地会话 Bearer 令牌、同源访问，POST 使用 JSON。

- `POST /api/session`：使用 `X-Model-Dock-Client: 1` 请求头自动建立页面会话，返回 `{session}`；拒绝其他来源的页面请求。
- `GET /api/state`：不含密钥的应用状态。
- `POST /api/connection`：提交 `revision, baseUrl, apiKey`，读取并连接授权目录。
- `POST /api/refresh`：提交 `revision`，刷新目录并保留失效选择。
- `POST /api/settings`：提交 `revision, models, routes`，原子保存完整草稿。
- `POST /api/run`：提交 `featureId, prompt` 及可选的 `modelId, reasoningEffort, stream`，解析功能后向网关发送 JSON/SSE 请求。

内部字段 `routes` 沿用旧命名，表示应用功能列表，不会发送给网关管理接口。完整字段与代码入口见 [英文接口说明](client-demo.md#demo-local-api)。
